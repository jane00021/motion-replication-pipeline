# 字幕复刻执行与六组认可案例

03首次制作、字幕返工或分发字幕任务时读取。本次六组获用户“非常之完美”认可，实际媒体、源码、输入、字体及配方摘要见 `assets/approved-subtitle-rework-v1/approval.json`。这是视觉效果认可，不确认原字体身份、听审或整个03通过。原项目不再是使用这些字幕执行器的前提。

## 先认结构，不能按金色重点字一律套T01

逐帧观察实际中文字面、字幕局部和全幅画面，保留完整动作与交接：

| 观察到的证据 | 对应机制及认可案例 | 执行入口 |
|---|---|---|
| 同一白字中线断开，上半上移、下半下移，中间金句揭晓 | split-title N07；split-line N21 | split_title.title_layers / split_rgba；closing.subtitle |
| 白句前后两段向左上、右下移动，中心交给金句 | diagonal-line N22 | closing.subtitle |
| 金中文从小虚到大实，下缘有独立可读红英文 | bilingual-title N13 | emphasis.subtitle(T08) |
| 整句金字每字错相起伏与倾斜 | gold-wave N17 | emphasis.subtitle(gold-wave) |
| 金字按字揭晓→清空→白前缀与金结论接力 | typed-relay N24 | closing.subtitle |

表格帮助识别已知机制，不要求新参考强行归入六类。找不到匹配时按证据实现新机制。普通主字幕分类不意味着可以忽略其颜色、描边、位置或字级运动。

同一白句切半，必须由一个真实文字层生成互补遮罩，不能复制两句完整白字。斜向让位可能按语义切成前后片段，不能误切成上下半字。红色外观可能是独立英文、投影或背衬：放大看可读字形并跨过程帧确认。不能看一张终态图就推断结构。

## 每组执行顺序

1. 固定起止帧；记录每个角色、表达职责、进入/揭晓/让位/保持/退出时点、遮罩与层序，写入项目测量证据。新台词重新选择重点角色、字词表和接力时钟。
2. 用参考原文做静态字体候选与实际墨迹宽高、基线、间距、轮廓、描边、阴影校准。先比较同字，不用不同内容证明字体准确。普通口播字保持自然比例；不能把每句压到同宽。N13固定字面属于当时标题校准参数，不能传播为正常字幕默认行为。
3. 为真实角色建立独立文本/font/style/events接口。英文不是中文阴影；首句与次句金字不一定同字号；按角色测量。字级入场顺序必须与当前字数匹配，不能沿用旧索引。
4. 采用下面真实执行器输出独立角色RGBA和合成RGBA。引用式完整组配方将字幕slot与画面slot放进同一时间轴，保留接力；字幕预览底色不能烘焙进透明层。
5. 实际编码，解码相同局部时点过程帧比较，覆盖入场、让位、揭晓、稳定、退出；列最大三处差异并返工。新台词延长时另外记录阶段对应帧，不能冒充同钟。
6. 检查自然字面、缺字、越界、层间遮挡、可见阴影、真实换字效果。顺序渲染后重新渲染关键帧，确认缓存未被揭字mask原地污染；检查稳定帧金字真实宽度，避免只剩窄条。切割零位移必须重合原字层。实际观看、技术播放、听审分别记录。

## 可直接使用的执行器

路径均相对skill-root，依赖 Python、Pillow、numpy、fontTools、ffmpeg。四个实际字体文件随认可案例保存，示例使用 `asset:fonts/...`，执行时相对案例目录解析，无需旧项目或D盘字体路径。

```powershell
python "<skill-root>/scripts/render_subtitle.py" --input "<skill-root>/assets/approved-subtitle-rework-v1/inputs/N21.json" --output "<新输出目录>"
```

输出 `roles/<slot>/*.png`、合成 `rgba/*.png`、独立底色 `preview.mp4`、逐帧alpha边界/摘要与编码/缓存检查 `verification.json`。不会改状态机，不会自动标用户通过。输出目录必须全新，防止覆盖已认可版本。

供新参考使用时：复制最接近的示例JSON到当前项目，改文本、角色字体和语义时钟，重测字面/位置；示例中的284×504工作画布、帧号、颜色、字号都是本片参数。执行器在284×504原生坐标工作；最终透明层可等比放大，更换构图比例须重新测量/实现，不能直接拉伸。固定inkWidth/inkHeight需明确 `measuredGlyphTransformEvidence`；普通字不用此字段。

源码模块在 `scripts/subtitle_engine/`；对项目组合可以导入 `render_subtitle.render_layers(config,n)`，返回具名RGBA slots，再由项目完整配方引用它。API输入需先 `resolve` 和 `validate`；保留模块摘要与参数摘要。N07/N21共用split_rgba原语，禁止复制两套切割实现。当前是执行能力与认可配方草案，不是04正式组件库。

## 可重复检查

```powershell
python "<skill-root>/scripts/check_subtitle_executor.py" --output "<独立空目录>"
```

真实重跑六套参数、输出编码与RGBA，检查案例文件摘要、缺字、连续渲染缓存稳定、换字影响像素、遮罩切半像素守恒。它验证实现能运行，不替代新参考的同字校准、过程视觉对照和用户审核。独立检验记录路径见 `assets/approved-subtitle-rework.json`。

## 调度约束

先复刻前两完整组给用户审核，认可后再按共用family分包并行。分发任务必须包含该参考的角色/遮罩/时钟证据、上述执行入口、同字校准及编码对照要求；不能只发“做成金色强调”。同一机制共用owner和代码，变体参数化；主进程检查其他输入的回归影响，再集成每组两播放器。用户的旧认可只绑定具体媒体摘要。
