# 拆解观察、用户校正与技能反馈

## 范围与模式

收到“当前在测试/反馈修改skill”时，在项目 `workflow-context.json` 写入 `mode: skill-test-feedback`、`feedbackRequired: true`、`stopBefore: 03-pilot`。当前任务是观察、学习反馈、修订技能；不能因用户说“继续”就转入复刻。流程是否进入下一节点与用户反馈是否已应用是两个独立结论。

## 三层拆解

先区分“原始底片/普通口播字幕”和“实际动效组件”。普通字幕的存在，不足以把画面组归成组合动效；用户指出是口播主字幕时，记 `ordinarySpeechCaption: true`，仅画面组的 `subtitle` 仍为null。同样，没有实际画面动作的普通人物视频不计画面family。

细查易漏的隐性组件：背景是否压暗/虚化，人物是否抠像遮挡身后文字或图形，普通主字幕是否另有重点词放大或纵向滚动，头顶贴图出现时是否同时伴随全画面放大。不要只看最显眼的图层。一组允许多个画面组件 `visualComponents` 和多个字幕组件 `subtitleComponents`；主family引用不代替完整组件表。明确 `layerOrder` 后→前，人物后的图形不能仍标为前景。补发现组件时先更新原完整组，不自动增加完整组数量。

1. **画面动效 family**：人物缩放/让位、遮罩、背景、前后景、素材运动与空间关系。普通人物底片不是额外的画面动效；静态图片和动态图层仍需分清。
2. **字幕动效 family**：文字的揭晓、强调、数字次序、标点、图形关系与进停退。字幕承载的数字、问号、警示符号或分支可能构成不同字幕机制，不能用它们把共同画面机制拆开。
3. **完整动效组 occurrence**：画面单独、字幕单独，或二者重叠/连续接力。完整组可跨换字、换图和镜头推进；不是连续时间切段。组件可以共享、重叠，空隙可为普通口播，不强制铺满原片。

先记录 occurrence，再分别归并两类 family，最后记录组合。每次归并依据：表达职责、图层顺序、几何与遮罩、动作时钟、入停揭晓退、字幕角色、声音落点。文字/素材/颜色/数字变化本身不构成新画面family。缩小与放大属于动作差异。原文、字幕可见时钟和声音无法确认时写 unknown，不推测成通过。

## 观察页默认交互

在01/02使用 `observations/decomposition-preview/`；标题显著写“仅拆解，不是复刻”，不占用正式 `preview/`。

```powershell
python "<skill-root>/scripts/prepare_observation_review.py" --project "<project>"
python "<project>/observations/decomposition-preview/review_server.py" --project "<project>" --port 8766
```

初始化后，将已观察候选写入 metadata.completeGroups（id、中文name、timecode、visual/subtitle引用）；FPS/总帧数由原片探测。没有候选不创建虚构卡片。

准备脚本现同时解码帧PTS，metadata.frameTimes保存每帧显示时间及exclusive终点；面板用索引查时间，而非frame/fps。分数帧率或VFR必须核对时间戳严格递增，实际浏览器检查不规则间隔两侧的前后逐帧定位；旧固定整数帧率计算不用于此类源。

每卡保留：中文可改名称、明确播放/暂停、逐帧、首末帧、起终点输入、当前位置设边界、全片定位、循环组内、合并下一组/撤销、备注、保存全部、JSON备份。面板读取原参考是为了修改边界，只能称参考校正播放器，不称独立复现。服务必须支持HTTP Range；浏览器实际测试seek，不以HTTP 200代替播放验证。终帧为exclusive；帧率不足以精确定位VFR时需时间戳索引。本脚本面板用于已确认整数CFR源，不能将avg_frame_rate当CFR证明。

修正必须体现在当前主名称与结构化组件中，不能仅加一句解释，仍让已否定的旧标签占据主输入框。旧名称和原备注存入折叠历史，原文件不覆盖；缓存载入时也要应用最新分类修订，保留用户边界。每卡明确标注并可更正 compositionMode：`visual-only`（仅画面）、`subtitle-only`（仅字幕）、`combined`（画面＋字幕动态组合）。顶部显示三种定义、数量和筛选；不存在的类型显示0，不虚构示例。卡片分别列明活动画面组件、字幕组件、表达目的和阶段接力；组合可重叠、连续接力或阶段切换，不能写成永远固定并列。普通人物底片在仅字幕组中明确说明不计额外画面动效。更新后用浏览器检查当前名称、分类、筛选、保存字段和缓存重载的一致性。

用户保存到 `observations/manual-review/adjustments.json`，旧版本自动备份。原始标注是证据，不覆盖、不替用户提交测试数据；浏览器本地缓存仅是草稿。保存次数不是用户认可次数。

## 用户反馈闭环（01中的显式子环节）

`候选拆解 → 中文校正页 → 用户边界/合并/备注 → 读取原始反馈 → 修订目录与搭配表达 → 展示修订及未确认项 → 再检查01/02门禁`

- 用源文件SHA256写 `feedback-applied.json`，注明 applied-not-stage-approved。
- 应用 startFrame/endFrame，不使用旧 timecode/reference 切片字段覆盖新边界；保留用户的间隙和重叠，若需完整组合的衔接范围另行说明。
- 用户明确某条“删掉”时，不删除原始标注；通过引用原备注和理由的解释记录 `excluded: true`，将条目从当前目录、面板及缓存恢复中排除，回执保存排除证据。合并成员与排除条目分别处理，不能凭旧缓存复活已移除的卡片。
- 展示用户原备注、旧判断、修改后的机制、证据、对后续搭配的影响。备注与UI合并不一致时保留两者，分析层注明关系，不篡改原文件。
- 更新 group-catalog 的 families.visual、families.subtitle、occurrences、completeGroups、variants，以及 measurements 的待测/已测状态。应用边界不代表完成逐帧量测。
- “画面×字幕搭配”每项注明表达目的、发生次序、谁接管表达、适用语义、原片occurrence证据、尚未验证的跨内容复用。不可称可任意搭配；可能挡脸、时钟冲突或职责冲突的组合需另测。
- 测试反馈模式的01/02报告必须引用真实 feedback-applied 文件，SHA与当前原始标注一致；需要逐帧/声音证据的未完成项仍写 unresolved。未经完整检查不accept。
- 修订技能只固化可泛化的方法、交互和门禁。某片的条数、具体标签、缩放值不作为所有视频固定要求。用户认可的是面板也不等于认可机制分类或复刻质量。

## 实际验证

### 动作与构图、family与实例的对照

- **切回不等于缩入**：看到框景／人物变小，先对照动作前、过程、落定帧。若只是硬切回已有构图，框与人物属于底片；仅强调字在动时归仅字幕。不要以静态构图倒推平移、缩放或遮罩动画。
- **同一人物让位机制的变体**：隐去背景内容、人物描边、素材与文字，比较人物的进入方式、遮罩、位置／缩放变化及让出信息区的职责。核心动作相同则用共同family，背景、描边、素材和实际位置大小存为实例变体；纯静态定位不冒充运动。圆形裁切与无裁切抠像等真实几何差异仍需分别检查，不机械合并所有人物窗。
- **连续不等于同组**：连续台词与素材切换只是线索。主体遮罩、几何和信息职责均重置，且上一表达已闭合时，可拆组；素材与文字沿共同机制完成连续论证时可合并。两种决定均引用动作过程与表达接力，不预设必须合或必须拆。
- **动作顺序写进机制**：底片先虚化、后切入清晰素材，与直接贴素材不是同一描述。把虚化、素材入场、后续剪影／指示等逐项写入组件及顺序；基础机制与附加组件分开，共用基础机制不重复计family。
- 片尾平台页、标记与静态框景先判断是否属于用户关注的内容动效；明确排除后不得由浏览器草稿或旧目录复活。默认提示备注未经用户修改不构成确认或排除意见。

### 备注要求拆分时的可审计应用

`apply_observation_feedback.py --interpretations <json>` 支持按原始标注ID给出 `sourceNote`、`reason`、`fields`；拆分另加 `split` 子组数组，每项含新id、startFrame、endFrame及当前名称／构成／组件。子组必须连续完整覆盖原标注最终范围，使用 `sourceAnnotationId` 记录父标注，`members`保留用户原合并成员。父标注保持原样；回执 `splits` 记录边界、原备注和理由。

内部拆分点是分析修订，需要动作前后帧证据；不能说成用户亲自标出的边界。非拆分解释不得改变用户ID、首末帧或合并成员；保留间隙、重叠。拆分后重新生成切片、过程帧、当前目录、family成员和面板。`validate_decomposition.py` 必须检查子组覆盖、ID唯一、原备注与SHA对应、无失效成员及类型／活动组件冲突。

`_families.visual/subtitle` 可给出修订后的机制定义；成员由当前活跃组重新生成。`_lessons` 保存可泛化学习项，`_unresolved`记录仍未确认项。不得从“很好”推断用户认可所有默认备注、量测或复刻质量。

应用后面板先比较反馈版本与保存时间：旧服务器标注／旧浏览器草稿以本次解释目录恢复；较新的人工编辑保留。明确排除项与拆分父ID始终过滤，旧合并子ID不得恢复。检查至少一次“旧缓存载入→应用目录出现→新修改→保存→重载”全流程，测试数据写独立副本。

维护脚本后运行 `scripts/test_observation_feedback.py`，并在新项目init中核对本地副本与assets；结构回归通过不代表下一条未见视频语义分类必然正确。

### 新视频首轮拆解检查

- 独立初始化新项目；不复制旧片的family数量、名称、时间码、素材或通过记录。
- 连续观察原片，先记录发生的动作事件及表达目的，再圈定完整表达单元；镜头切点仅作线索，不能直接变成完整组。
- 每个候选保留入场前一帧、动作首帧、揭晓/停留帧、动作末帧和交接后一帧证据。候选可跨转场，也可只占镜头的一部分；裁切不能含下一独立动作，不能截掉本组的铺垫或退场。未逐帧核对不得说精确裁切。
- 做两次对照：隐去文字/素材内容比较共同画面机制；固定画面再比较字幕机制。只因数字/图片/颜色不同而拆开的画面family应合并。
- 完整组核对谁先铺垫、谁接管、是否重叠/连续接力、什么语义结束这一组；不强制连续铺满全片，不按等长切片。
- 当前主名称、compositionMode、活动组件、family成员、起终帧、原备注解释及面板显示同步一致。备注优先级需人工理解，不能凭关键词自动分类；与旧下拉选择冲突时，用带原备注引用和理由的解释记录修订分析层，保留原始文件。
- 在展示第一版前实际浏览器检查播放、逐帧、组内循环、三种类型筛选、合并/撤销、保存/重载；不把HTTP200或格式检查称为视觉正确。

### 可执行反馈应用与结构检查

```powershell
python "<skill-root>/scripts/apply_observation_feedback.py" --project "<project>"
python "<skill-root>/scripts/validate_decomposition.py" --project "<project>"
```

应用脚本以最终17或其他实际条数的原始记录为准，重新生成目录、family成员、面板当前修订与测量待办，不再沿用被合并消失的旧条目；绝不把该样本条数写死。存在明确备注解释时可加 `--interpretations <json>`，每项须引用当前原备注sourceNote、reason及fields，不暗改用户原文件。保存后的新SHA令旧回执失效。

结构检查拦截类型/组件冲突、旧family成员、漏用最终边界及过期反馈；它不证明原片语义正确。用户明确本轮拆解无问题时单独保存认可的对象范围与反馈SHA，不冒充02数值量测或复刻质量认可。新视频用第一版效果独立验证技能，不能承诺未经新样本测试就必定一次无误。

在浏览器检查中文卡片、播放、跨关键帧seek、逐帧、循环边界、改名、缩短/扩展范围、合并/撤销、备注保存与重载。保存API的持久化/历史备份用临时目录验证；勿污染真实标注。修改技能时验证新项目 init 的本地副本也带有本参考、面板assets和准备脚本，避免仅修改全局文档而项目恢复仍走旧流程。
