# 阶段执行手册

每个阶段都必须在项目目录中留下可审计产物。报告中的“通过”必须引用实际文件、帧图、视频或日志。

## 00-intake：接收与固定范围

执行：

1. 确认参考视频真实存在，记录 SHA256。
2. 运行 `probe`，取得时长、宽高、帧率、视频流和音频流。
3. 固定目标画幅、是否需要人物替换、是否需要字幕可换字和字体可换。
4. 记录工具能力：FFmpeg/ffprobe、字体加载、渲染器、浏览器、音频观察方式。

产物：`project.json`、`artifacts/00-intake/source-probe.json`、`source-manifest.json`、`scope.json`。

通过条件：真实源文件和范围明确；缺失能力写入 blocker。

## 01-observe：完整观察、实例目录与机制归类

本节点包含显式的用户反馈子环节。先读 `decomposition-feedback.md`，使用技能提供的中文可保存校正面板；用户反馈后应用真实边界/备注并解释画面×字幕搭配。测试反馈模式在本环节修订skill，不自动推进到复刻。

执行：

1. 实际浏览整条参考视频，建立镜头时间线。
2. 先登记每一次实际出现的 `occurrence`，记录来源起止时间、台词、人物状态、素材和声音落点。
3. 分别按“表达目的 + 分层结构 + 几何关系 + 动作时序 + 进退场编舞”归并画面family与字幕family，再记录完整组的单独、重叠或连续接力关系；文字、图片和事件时点不同不能单独制造新画面组。
4. 只有机制或构图真的不同，才建立新的 family；同一 family 的不同内容作为 `variants` 或多个 occurrence 保存。
5. 为每个 family 生成原片切片、联系表和关键过程帧，并在目录中列出全部 occurrence。
6. 给用户可逐帧改边界、合并、改名、备注并持久化的观察页。读取 adjustments.json，保留原始反馈，另写 feedback-applied.json；更新组合关系、搭配表达和待测项。用户反馈还需再修订时保持本节点active。

产物：`observations/group-catalog.json`、`observations/shot-index.json`、`observations/contact-sheet.*`、`observations/groups/<family-id>/reference-clip.*`。

通过条件：每个 occurrence 有来源时间码，每个 family 有机制定义、功能、台词关系和过程帧；同一机制换文字不重复计组；family 与 occurrence 数量明确区分。

本节点禁止：生成复刻视频、换内容版、换字体版、可编辑模板或把参考片段标成“原素材基准”。如果需要给用户看，只能提供参考片段和拆解观察页，并在页面显著标注“仅拆解，不是复刻”。

## 02-measure：逐帧和分层测量

执行：

1. 画面组记录每层的几何、裁切、遮罩、深度、入/停/退关键帧。
2. 字幕组记录逐句/逐词/逐字时间、字体文件、字重、字号、行距、基线、描边、阴影和高亮角色。
3. 记录所有“未知”项，不用猜测填充；如果只能得到近似值，注明测量方法和误差范围。
4. 对需要替换的图片、人物和音效记录来源与许可。
5. 逐项检查用户修订过的边界与机制，不把应用标注当成完成字级时钟、声音、缩放量测。画面×字幕的搭配注明实际表达目的及尚未验证的复用范围。

产物：`measurements/visual-groups.json`、`measurements/subtitle-groups.json`、`measurements/fonts.json`、`measurements/assets.json`。

通过条件：关键差异能定位到帧号、对象和下一步修改；能据此写出分层配方。

本节点仍禁止生成任何 baseline、changed-content、changed-font 或最终 HTML 复刻卡片；这些只能在 `03-pilot` 之后出现。

## 03-pilot：代表组原素材复现

先读 `replication-calibration.md`。先用同字静态字形、排版与材质（特别阴影）校准，再以过程帧重建动作，真实编码后按同局部时间找最大差异并返工。用户提供干净新口播时，用独立透明组件验证迁移；禁止把旧清字补丁带进结果。界面认可单独记录具体媒体SHA和范围，不能自动变成整个阶段通过。

执行：

1. 选择至少一组画面动效和一组字幕动效，必要时加一组复杂交接组。
2. 用真实字体、真实素材和同一时间轴实现原素材基准版。
3. 编码后连续观看入场、中段、停留、退场和下一镜交接。
4. 发现不像时，优先检查素材、字体、分层和时钟假设，再调参数。

产物：`source/`、`baseline/`、`render/pilot/`、`reviews/pilot-review.json`。

通过条件：代表组机制成立，源码不是整片重播，且保留参数入口。

## 04-library：完整动效库与去重归类

### 后处理批次

在03通过后，04到07通常属于同一后处理批次。一次批次可以连续完成组件整理、已有替换结果导入、编码复审和HTML面板。状态机仍保留04、05、06、07四份报告和四次收据，用于分别核对库入口、替换证据、编码结果和展示入口。

按 [认可成果入库执行](library-intake.md) 核对认可媒体、输入及源码。先交付“来源完整组 → 画面组件 → 字幕组件 → 原组合配方”映射；按机制分批入库并重跑受影响原配方。组件接口独立，配方只引用确定版本，在共享时钟上保留层级、接管与退出。默认暂停新搭配。

产物：活动 library/catalog.json、机制映射、共享源码与参数合同、独立组件预览、原配方真实编码回归收据、三类浏览面板。原配方回归对照留在工程验证记录。

通过条件：认可范围可追溯，组件可独立渲染，原组合由共享入口重跑并保持原效果。运行 library_intake.py verify 检查回归覆盖与文件版本；字体、层级、节奏、透明和声音按实际检查补证。前置节点未通过时只记候选入库，不推进状态。

## 05-replacement：换内容与换字体

本节点有两种执行模式。\`generate\` 用于当前项目没有可追溯替换结果的情况。\`import\` 用于03期间已经完成并展示过替换人物、换内容或换字体的情况。import 需要逐项绑定实际媒体、输入参数、源码入口、实际字体文件、透明层或编码输出、SHA256、适用组和检查记录。它只完成节点证据整理，不重新渲染。

执行：

1. 先扫描03和复刻审核目录，建立替换证据清单。
2. 已有证据满足绑定要求时，使用import模式验收媒体、源码、参数和SHA。
3. 没有证据时，用新人物、台词或图片生成换内容版，并用至少两种字体生成换字体版。
4. 检查缺字、字宽、换行、基线、安全区、人物遮挡和素材残留。
5. 测试短文、长文、空字段、不同项数和不同事件时点。已在03完成并记录的项目沿用实际检查记录，不重复生成。

产物：`variants/changed-content/`、`variants/changed-font/`、`contracts/replacement-matrix.json`。

通过条件：generate模式下替换确实改变渲染且无烧字、硬编码旧内容、溢出和旧素材残留。import模式下每个替换结果都有实际文件、参数、源码、字体和SHA绑定，检查范围与结果一致。

## 06-encoded-review：编码后声画复审

执行：

1. 输出 H.264 兼容 MP4，完整解码。
2. 对每个声明画幅连续观看动作过程。
3. 实际检查人声、BGM、FX 与可见动作和语义转折的关系。
4. 记录具体问题，例如“动作尾声在人声下听不清”，不要只写“音效偏小”。

产物：`render/<layout>/final.mp4`、`reviews/encoded-review-<layout>.json`、`qa/decodes.json`。

通过条件：视频可连续播放，声画时钟和编码结果与复审记录对应。

## 07-html-preview：HTML 展示面板

执行：

1. 为每个动效组生成独立卡片，不把完整参考视频当作一个卡片。
2. 每卡展示原素材基准、换内容版和换字体版。
3. 提供播放/暂停、时间轴拖动、逐组定位、画幅切换和参数输入。
4. 显示功能分类、来源时码、已验证范围和已知限制。
5. 运行 `validate-html`，再用浏览器实际打开、播放、拖动和切换。

产物：`preview/index.html`、`preview/app.*`、`preview/assets/`、`preview/metadata.json`、`reviews/html-review.json`。

通过条件：浏览器能加载全部卡片，视频连续播放，控件有效，替换版不是静态占位图。

## 08-cleanroom：独立目录复用

执行：

1. 创建全新目录，只放交付包/源工程和第二份新输入。
2. 不回读原项目、缓存、旧样片或旧通过记录。
3. 测试默认内容、长文本、项数变化、迁移路径和声明画幅。
4. 对新输入再次编码、观看和试听。

产物：`cleanroom/`、`cleanroom/cleanroom-review.json`、`cleanroom/cleanroom-video.*`。

通过条件：脱离作者目录仍能运行，且画面和声音不依赖旧样片。

## 09-release：封版与交接

执行：

1. 固定版本、SHA256、源码入口、运行命令和支持环境。
2. 区分内部复审、用户明确认可和未验证范围。
3. 保留旧版本和反馈记录，后续修改从最早受影响节点回退。
4. 生成 `RELEASE.md` 和新的 `HANDOFF.md`。

产物：`release/manifest.json`、`release/RELEASE.md`、`HANDOFF.md`。

通过条件：交付版本与清洁目录验证的是同一份包，限制和支持范围清楚。
